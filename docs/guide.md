# 开始使用

## 下载与安装

前往 [下载页面](https://github.com/yeyongzhi/onTime/releases)，选择与你的系统匹配的安装包。Windows 使用 `.exe`，macOS 使用 `.dmg`；实际可用的版本以下载页面为准。

Windows 安装包目前未签名，首次运行可能出现未知发布者提示。macOS 安装包目前未完成 Developer ID 签名和公证。请确认安装包来自项目的 GitHub Releases。

## 本地数据目录

首次打开应用会自动初始化数据，无需先选择目录。Windows 默认使用程序安装目录；macOS 默认使用系统用户数据目录，避免写入只读应用包。已有自选数据目录继续沿用。提醒、铃声、配置与日历均保存在实际数据目录，可在“设置 → 数据”查看并点击“打开本地目录”。安装目录不可写时，请选择可写的本地数据目录。

设置中的“数据”提供两种操作：

- **切换数据目录**：打开所选目录中的数据，不复制原目录内容。
- **迁移数据**：选择空目录，复制提醒、历史、铃声与设置并切换；原目录保留。迁移前需处理所有响铃和贪睡中的提醒。

## 创建第一个提醒

点击“新建提醒”，填写名称，选择定点提醒或倒计时。设置时间与重复规则，按需选择铃声，打开“保存后启用”，最后保存。

一次性提醒完成后会自动停用。重新启用或修改倒计时时长会重新开始计时；普通编辑保留当前截止时间，也可在“铃声与高级”中主动选择保存时重新计时。离开未保存的编辑内容前，应用会询问是否放弃。

## 重复提醒的多个时间

重复维度可选每天、每周、每月、每季度或每年。提醒时间可选择“自定义多个时间”，逐项添加，例如 09:00、10:00、11:00；重复的时间会自动合并。

也可选择每半小时、1 小时或 2 小时提醒。每半小时从下一个整点或半点开始，1 / 2 小时从下一个整点开始；2 小时提醒按首次起点持续间隔 2 小时。勾选“跳过下一个时间点”会跳过首次时间点，距下一个点不超过 5 分钟时默认勾选，可自行取消；悬停问号查看说明。

新建倒计时时，下一次提醒预览随时间每秒刷新；编辑已运行倒计时仍保留原截止时间，除非选择重新计时。

## 让提醒持续运行

关闭主窗口后，应用仍在托盘运行。首页与托盘的“查看活动提醒”可以重新打开响铃和贪睡中的提醒；收起响铃窗后，本次提醒继续响铃，直到停止或自动结束。可从托盘重新打开主窗口或退出；也可在“设置 → 常规”开启登录自启动。退出应用会停止提醒。

## 备份你的安排

在“设置 → 备份”导出备份，妥善保存 ZIP 文件。恢复会替换当前数据，并取消当前及备份中的响铃和贪睡状态，避免旧提醒再次响起；应用会保留恢复前备份。操作前请确认所选文件。

## 历史保留与清理

“设置 → 数据”的历史保留策略默认永久保留，也可选 30、90、180 或 365 天。每日备份成功后清理已结束的旧记录，正在响铃和贪睡的记录保留。

手动“清理历史与未使用铃声”会先备份业务数据及未使用铃声，再按策略删除旧历史和未被已保存提醒引用的铃声。清理前请先保存编辑中的提醒；备份文件不在清理范围内。

历史分类在触发时保存。旧版缺少分类快照的记录会按升级时信息补全并标注；原提醒已删除且无法补全的记录会显示类型未知。

## 检查新版本

应用启动后及持续运行时自动检查更新，同一数据目录自动检查最多每 6 小时一次；“设置 → 关于”可手动检查，手动检查无冷却，每次点击都会重新请求更新源；检查进行中不能重复发起。稳定版和预览版均纳入检测。

更新信息优先读取官网静态清单，清单在三个安装包全部发布、校验信息齐全后更新。官网不可用时才有限度地尝试 GitHub API；遇到限流会显示可重试时间，详细错误写入本地日志。

网络失败时保留上次成功结果，并明确显示“上次成功检查”时间，不会把旧缓存当作刚确认的最新版本。可以点击“前往发布页”手动下载。

下载安装包后应用会校验 SHA-256，通过后才保存为完整安装包；校验失败会丢弃临时文件。Windows 安装版可点击“更新并重启”：应用自动缓存安装包、校验完整性、备份数据，退出后覆盖原安装目录并重新打开，不再需要手动保存或双击 EXE。若有未保存的提醒编辑，会先询问是否离开；取消后更新仍保留，可稍后点击“安装并重启”。安装启动失败时应用保持运行，安装失败时尝试重新打开原程序并提示失败。macOS 和开发 / 免安装运行仍使用手动下载安装包流程；切换页面不会丢失下载进度。

beta3 / beta4 仍直接使用 GitHub API，遇到限流需要先从 [beta6 发布页](https://github.com/yeyongzhi/onTime/releases/tag/v0.0.1-beta6) 手动下载安装包，之后才能使用新机制；beta1 / beta2 同样建议手动升级。

从 beta5 升级到 beta6，仍需手动打开下载的安装包一次；安装 beta6 后，Windows 安装版的后续更新可自动安装并重新打开应用。
